01 The problem

You keep saying it. It keeps forgetting.

  • ×
    "Run dotnet format after you edit."
    Does it twice, then forgets.
  • ×
    "Never touch the EF migrations folder."
    Three prompts later, edits a migration.
  • ×
    "Run the tests before you say you're done."
    Says "done" with a red build.

Instructions in CLAUDE.md are suggestions the model tries to follow. They are probabilistic. On a long session, under heavy context, they drift.

02 What is a hook?

A hook is code that always fires.

A hook is your shell command, run deterministically at a fixed point in the agent's lifecycle - before a tool runs, after an edit, when it tries to finish.

CLAUDE.md

A suggestion the model may follow. Fades under context.

A hook

Code that runs every time, no matter what the model decides.

03 The mental model

Event → Matcher → Handler

Event
A moment
PreToolUse, PostToolUse, Stop, SessionStart...
→
Matcher
A filter
Only fire for these tools: Bash, Edit|Write
→
Handler
Your command
Gets event JSON on stdin. Talks back via exit code + stdout.

That is the whole thing. Event fires, matcher checks, your command runs with JSON on stdin, Claude reads the result and acts.

04 How your command talks back

Three exit codes. That's the whole protocol.

ExitMeaning
0All good, carry on. Valid JSON on stdout is applied. On SessionStart / UserPromptSubmit, stdout is added to Claude's context.
2Block it. PreToolUse blocks the tool, Stop refuses to finish, UserPromptSubmit blocks the prompt. Your stderr is fed back to Claude.
otherNon-blocking warning. The action proceeds; stderr is shown to you.

clean way

For structured control, return JSON on stdout with permissionDecision and a reason - shown on the guardrail slides.

05 Where config lives

One committed file. Your whole team inherits it.

~/.claude/settings.jsonAll your projects - personal, not committed.
.claude/settings.jsonThe money file. Committed to git - every teammate gets the same rules.
.claude/settings.local.jsonThis project, personal, git-ignored.

convention

Put scripts in .claude/hooks/ and reference them with ${CLAUDE_PROJECT_DIR} so they resolve wherever the session started.

Recipe 1 Auto-format C# after every edit

Claude edits a .cs file → your formatter runs.

what happens

Claude writes OrderService.cs, the hook fires, whitespace and usings get fixed. Claude never fights the reformat - the file is just correct.

faster

dotnet format feels slow? Swap the command for CSharpier - csharpier format "$file_path" formats a single file in milliseconds.

Recipe 2 Protect files Claude must never touch

Migrations, generated files, prod config - read-only.

what happens

Claude tries to "fix" a migration, the hook denies it, Claude reads the reason and does the right thing - it creates a new migration instead.

Recipe 3 Block dangerous shell commands

Force-push, drop database, rm -rf - not on your watch.

what happens

Claude proposes git push --force, the hook kills it, the message lands in Claude's context, it backs off. Your main branch survives the night.

Matcher: "Bash" on the PreToolUse event.

Recipe 4 · the hero Don't let Claude finish on a red build

The Stop gate: "done" means the build is green.

what happens

Claude says "All set!", the hook builds red, exit 2 sends the errors back, Claude fixes them, tries again, green, done. You get a working tree - not an optimistic summary.

loop safety

A gate that never passes loops the agent. Keep the check fast and achievable - a build or one focused unit project, not the 20-minute integration suite.

Recipe 5 Inject your conventions at session start

Stop pasting your architecture every time.

On SessionStart, whatever your script prints to stdout is added straight to Claude's context.

what happens

Every new session, Claude already knows your architecture and what's currently dirty in the tree - before you type a word.

pair it

CLAUDE.md for the stable rules, this hook for the live state. Want it on every prompt? Use UserPromptSubmit + additionalContext.

Recipe 6 Tell me when you need me

Long run, you tabbed to Slack. Get pinged.

  • Windows / PowerShell:  [System.Media.SystemSounds]::Asterisk.Play() or BurntToast

08 Two rules before you go wild

Powerful means handle with care.

Rule 1 · Security

Hooks run arbitrary shell with your full permissions, automatically. Keep scripts in the repo so they're reviewable in PRs. Never source a hook from somewhere you don't control.

Rule 2 · Don't over-block

A guardrail that fires on everything turns the agent into a wall. Block the genuinely dangerous; format, notify and load context freely. Aim for an agent that's safe to leave running.
